## Phase 2 — Organ-to-contract alignment

This is an architectural target map, not a statement of runtime conformance. “Produces” and “consumes” below describe intended boundary roles once adapters exist; they do not claim that the current code serializes or validates the Spine schemas.

**Contract naming:** `telemetry_contract` is the snapshot contract. Creature lists, hunger, fear, and corruption values are fields within a telemetry snapshot, not separate creature/corruption contracts. There is no separate `snapshot_contract`, `creature_contract`, or `corruption_contract` in this Spine version. World definitions/region identities belong to `world_contract`; runtime measurements belong to telemetry. Internal implementation files inherit their module's manifest but do not individually implement `module_contract`.

## Status definitions

- **Exists in code?** “Related subsystem exists” is not proof that the named recovered behavior exists.
- **Verified?** `Yes` means source/status was checked in this checkout; `Partial` means only part of the interface or behavior is confirmed; `No` means the specific concept or external source is unverified.
- **Needs implementation?** `Unknown` is deliberate where source review is insufficient to decide whether work is missing.
- **Needs integration?** `Yes` means no end-to-end Spine conformance was established.
